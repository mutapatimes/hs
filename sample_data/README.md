# sample_data/ — synthetic files only

This folder holds synthetic data and nothing else. Every file here is named `synthetic_*.xlsx`
and was generated by `scripts/make_synthetic_data.py`; none of it describes a real person.

Real customer exports never enter this repository. They live in the vault, a folder outside the
checkout that only this user can read: `HALIA_REAL_DATA_DIR`, by default `~/HaliaVault`. Scripts
that score a real export take the file's name and resolve it from the vault
(`halia.datavault.real_source`); a real file dropped in here by mistake is refused by the loader,
not scored.

Anything published under `web/` or `docs/` is built from a synthetic file and nothing else
(`halia.datavault.public_safe_source`). The pre-commit hook, CI and the app's own start-up check
refuse text that carries the tells of a real export. See `docs/data-handling-policy.md`.

The folder is git-ignored apart from this README and is tracked only through it. Before pushing:

    git ls-files sample_data/      # only this README.md
    python scripts/check_no_pii.py # clean
